# Feature Specification: TikTok Creator Insight Assistant MVP

**Feature Branch**: `001-tiktok-creator-insight`  
**Created**: 2025-01-27  
**Updated**: 2025-01-05 (三阶段交互方案)  
**Status**: Draft  
**Input**: User description: "构建一个TikTok Creator Insight Assistant MVP，帮助短视频创作者将创意意图转化为结构化脚本大纲与趋势洞察。支持多语言输入、生成3种不同风格的脚本、5-10个Hashtag和音乐风格建议，并提供卡片式结构化展示。"

## 核心设计变更：三阶段协作式创作流程

**设计理念**：从"一次性生成"转变为"协作式创作"，通过三个阶段逐步收敛用户意图，提升生成质量和用户满意度。

### 三阶段流程概览

1. **阶段1：金句选择（Hook Selection）** - 找到能引起共鸣的"金句/钩子"
2. **阶段2：内容创作（Content Development）** - 围绕金句展开丰富的内容
3. **阶段3：脚本转换（Script Conversion）** - 将内容转换为可执行的短视频脚本

**核心特性**：
- 每个阶段都支持迭代优化（替换、微调、编辑）
- 支持回退到上一阶段修改
- 会话状态持久化（支持刷新后恢复）
- 每个阶段都有明确的确认机制

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 创意意图输入与识别 (Priority: P1)

创作者打开应用，在输入界面输入他们的创作主题或目标赛道（支持中文或英文），系统识别并理解用户的创意意图。

  **Why this priority**: 这是整个应用的核心入口，没有输入功能，后续的AI生成功能无法工作。这是MVP的最小可行功能。

**Independent Test**: 可以独立测试：用户输入文本后，系统能够正确接收、显示并准备处理输入内容。即使没有AI生成功能，输入界面本身也能展示价值（用户可以看到自己的输入被正确记录）。

**Acceptance Scenarios**:

1. **Given** 用户打开应用，**When** 用户在输入框中输入创作主题（如"美食探店"），**Then** 系统显示用户输入的文本，并准备提交处理
2. **Given** 用户输入英文内容（如"food review"），**When** 用户提交输入，**Then** 系统能够识别并处理英文输入
3. **Given** 用户输入中文内容（如"旅行vlog"），**When** 用户提交输入，**Then** 系统能够识别并处理中文输入
4. **Given** 用户输入目标赛道（如"美妆"），**When** 用户提交输入，**Then** 系统能够识别赛道信息并准备生成相关内容

---

### User Story 2 - 三阶段协作式创作流程 (Priority: P1) [新设计]

用户通过三个阶段逐步完善创作内容：阶段1选择金句、阶段2创作内容、阶段3生成脚本。每个阶段都支持迭代优化和回退修改。

**Why this priority**: 这是产品的核心价值主张 - 通过协作式创作提升脚本质量和用户满意度。三阶段设计解决了"一次性生成质量不稳定"和"用户参与度低"的问题。

**Independent Test**: 可以独立测试：用户输入主题后，系统引导用户完成三个阶段，每个阶段都有明确的交互和确认机制。即使某个阶段失败，用户仍可以回退修改。

**Acceptance Scenarios - 阶段1：金句选择**:

1. **Given** 用户已输入创作主题（如"新年美食探店"），**When** 系统生成金句选项，**Then** 系统返回3-5个金句卡片供用户选择
2. **Given** 系统展示金句选项，**When** 用户点击"替换"按钮，**Then** 系统生成新的金句选项替换当前展示
3. **Given** 用户选中某个金句，**When** 用户点击"微调"按钮，**Then** 系统基于选中的金句进行优化生成
4. **Given** 用户手动编辑金句，**When** 用户点击"优化此句"，**Then** 系统基于编辑后的金句进行优化
5. **Given** 用户对某个金句满意，**When** 用户点击"这个金句不错，继续创作内容"，**Then** 系统进入阶段2，并保存选中的金句

**Acceptance Scenarios - 阶段2：内容创作**:

1. **Given** 用户已选择金句并进入阶段2，**When** 系统生成内容大纲，**Then** 系统返回3个详细的内容要点（不是简单大纲，而是丰富的内容描述）
2. **Given** 系统展示内容大纲，**When** 用户编辑任意要点，**Then** 系统保存编辑后的内容
3. **Given** 用户查看内容大纲，**When** 用户点击"优化内容"，**Then** 系统基于当前内容重新生成优化版本
4. **Given** 用户点击某个要点，**When** 用户点击"基于此要点展开"，**Then** 系统针对该要点进行深入展开
5. **Given** 用户对内容满意，**When** 用户点击"内容满意，生成脚本"，**Then** 系统进入阶段3，并保存内容大纲

**Acceptance Scenarios - 阶段3：脚本转换**:

1. **Given** 用户已确认内容并进入阶段3，**When** 系统生成脚本，**Then** 系统返回3种不同风格的脚本卡片（故事叙述型、教程教学型、对比评测型）
2. **Given** 系统生成脚本，**When** 脚本包含结构化要点，**Then** 每个脚本包含情绪锚点、信息密度控制、反转/冲突设计、记忆点植入等专业元素
3. **Given** 用户查看脚本卡片，**When** 用户点击"优化此脚本"，**Then** 系统基于该脚本进行微调优化
4. **Given** 用户查看脚本，**When** 用户点击"一键复制"，**Then** 对应脚本的内容被复制到剪贴板

**Acceptance Scenarios - 会话管理**:

1. **Given** 用户正在进行创作流程，**When** 用户刷新页面，**Then** 系统能够恢复会话状态，显示当前阶段和已保存的内容
2. **Given** 用户在阶段2或阶段3，**When** 用户点击"返回上一阶段"，**Then** 系统返回上一阶段，允许用户修改之前的选择
3. **Given** 用户完成所有阶段，**When** 用户开始新的创作，**Then** 系统创建新的会话，不影响之前的会话数据

---

### User Story 3 - Hashtag与音乐风格建议生成 (Priority: P2)

系统在用户完成三阶段创作流程（Stage 3）后，基于完整的创作上下文（金句、内容大纲、生成的脚本），生成5-10个高潜力Hashtag标签和背景音乐风格描述建议。

**Why this priority**: 这是增强功能，帮助创作者提升内容曝光度。虽然重要，但可以在脚本生成功能之后实现，不影响核心MVP价值。在三阶段设计中，Hashtag和音乐建议应该在Stage 3完成后生成，以便更好地匹配最终脚本内容。

**Independent Test**: 可以独立测试：用户完成Stage 3后，系统生成Hashtag和音乐建议，以独立卡片或区域展示。即使脚本生成失败，Hashtag和音乐建议仍可独立提供价值。

**Acceptance Scenarios**:

1. **Given** 用户已完成Stage 3并生成脚本，**When** 系统生成内容建议，**Then** 系统返回5-10个与脚本内容相关的Hashtag标签
2. **Given** 系统生成Hashtag建议，**When** 展示给用户，**Then** Hashtag以可点击或可复制的形式展示
3. **Given** 系统生成音乐建议，**When** 展示给用户，**Then** 系统提供背景音乐风格描述（如"轻快节奏"、"舒缓背景音"等），不包含实际音乐文件
4. **Given** 用户查看Hashtag建议，**When** 用户点击复制按钮，**Then** 所有Hashtag被复制到剪贴板

---

### Edge Cases

- **空输入处理**: 当用户提交空输入或仅包含空白字符时，系统显示友好的错误提示，要求用户输入有效内容
- **API调用失败**: 当AI API调用失败（网络错误、超时、认证失败）时，系统显示用户友好的错误消息，提供重试选项
- **API响应超时**: 当API响应时间超过30秒时，系统显示超时提示，允许用户取消或重试
- **部分内容生成失败**: 当脚本生成成功但Hashtag生成失败时，系统仍展示已成功生成的内容，并提示部分功能暂时不可用
- **输入内容过长**: 当用户输入超过500字符时，系统提示输入过长，建议精简内容
- **特殊字符处理**: 当用户输入包含特殊字符或emoji时，系统能够正确处理并传递给API
- **多语言混合输入**: 当用户输入中英文混合内容时，系统能够识别并处理
- **数据库连接失败**: 当数据库启用但连接失败时，系统继续正常工作，不中断用户请求，仅在日志中记录错误
- **数据库磁盘空间不足**: 当数据库磁盘空间不足时，系统继续正常工作，数据库操作失败不影响产品功能
- **数据库文件损坏**: 当数据库文件损坏时，系统自动禁用数据库功能，继续正常工作
- **数据库启用/禁用切换**: 系统可以在运行时通过环境变量切换数据库启用状态，无需重启（如果支持）或重启后生效

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供简洁的文本输入界面，支持用户输入创作主题或目标赛道
- **FR-002**: 系统 MUST 支持中文和英文两种语言的输入识别和处理
- **FR-003**: 系统 MUST 在用户提交输入后，调用AI模型API生成内容
- **FR-004**: 系统 MUST 生成3个不同风格的短视频脚本大纲（风格差异必须明显，如：故事叙述型、教程教学型、对比评测型）
- **FR-005**: 系统 MUST 生成5-10个与主题相关的高潜力Hashtag标签
- **FR-006**: 系统 MUST 生成背景音乐风格描述建议（文字描述，不包含实际音频文件）
- **FR-007**: 系统 MUST 使用卡片式布局展示所有生成的内容（脚本、Hashtag、音乐建议）
- **FR-008**: 系统 MUST 在API调用过程中显示Loading状态指示器
- **FR-009**: 系统 MUST 实现错误处理机制，当API调用失败时显示友好的错误消息
- **FR-010**: 系统 MUST 为每个生成的内容卡片提供"一键复制"功能
- **FR-011**: 系统 MUST 在内容复制成功后向用户显示确认提示
- **FR-012**: 系统 MUST 验证用户输入不为空且长度合理（建议1-500字符）
- **FR-013**: 系统 MUST 集成阿里云百炼平台API（使用DeepSeek-V3、DeepSeek-R1或Qwen-Max模型）
- **FR-014**: 系统 MUST 安全存储API密钥，使用环境变量管理，不将密钥提交到版本控制
- **FR-015**: 系统 MUST 支持SQLite数据库用于会话持久化（必需）和开发调试（可选）
- **FR-016**: 系统 MUST 通过环境变量控制数据库的启用/禁用（`ENABLE_DATABASE=true/false`）
- **FR-017**: 当数据库启用时，系统 MUST 记录API请求和响应到SQLite数据库（用于开发调试和历史查询，可选功能）
- **FR-018**: 当数据库禁用时，系统 MUST 正常处理所有用户请求，但会话持久化功能将不可用
- **FR-019**: 系统 MUST 在启动时检测数据库可用性，如果不可用则禁用数据库功能，但会话功能必须可用

### 三阶段协作式创作功能需求 (FR-028 - FR-050)

#### 阶段1：金句选择 (FR-028 - FR-033)

- **FR-028**: 系统 MUST 在用户输入创作主题后，生成3-5个金句选项供用户选择
- **FR-029**: 系统 MUST 支持用户点击"替换"按钮生成新的金句选项
- **FR-030**: 系统 MUST 支持用户选中金句后点击"微调"按钮进行优化
- **FR-031**: 系统 MUST 支持用户手动编辑金句后点击"优化此句"进行优化
- **FR-032**: 系统 MUST 在用户确认金句后保存到会话状态，并进入阶段2
- **FR-033**: 金句 MUST 具有强烈的吸引力和情感共鸣，能够作为短视频的"钩子"

#### 阶段2：内容创作 (FR-034 - FR-040)

- **FR-034**: 系统 MUST 基于选定的金句生成3个详细的内容要点（不是简单大纲，而是丰富的内容描述）
- **FR-035**: 系统 MUST 在阶段2始终显示选定的金句，保持上下文可见
- **FR-036**: 系统 MUST 支持用户编辑任意内容要点
- **FR-037**: 系统 MUST 支持用户点击"优化内容"重新生成内容大纲
- **FR-038**: 系统 MUST 支持用户点击"基于此要点展开"深入展开某个要点
- **FR-039**: 系统 MUST 在用户确认内容后保存到会话状态，并进入阶段3
- **FR-040**: 内容要点 MUST 详细丰富，包含具体场景、情感、细节，而不仅仅是结构化的标题

#### 阶段3：脚本转换 (FR-041 - FR-046)

- **FR-041**: 系统 MUST 以"短视频拆解大师"的角色将内容转换为脚本
- **FR-042**: 系统 MUST 生成3种不同风格的脚本（故事叙述型、教程教学型、对比评测型）
- **FR-043**: 脚本 MUST 包含专业元素：情绪锚点、信息密度控制、反转/冲突设计、记忆点植入
- **FR-044**: 系统 MUST 支持用户点击"优化此脚本"对单个脚本进行微调
- **FR-045**: 系统 MUST 以结构化卡片形式展示脚本，包含标题、风格、要点、专业元素标注
- **FR-046**: 系统 MUST 在阶段3始终显示金句和内容大纲，保持完整上下文

#### 会话管理与状态持久化 (FR-047 - FR-050)

- **FR-047**: 系统 MUST 为每个创作流程创建独立的会话（Session），包含唯一ID
- **FR-048**: 系统 MUST 持久化会话状态（阶段、金句、内容大纲、生成的脚本），支持刷新后恢复（必需功能，依赖数据库）
- **FR-049**: 系统 MUST 支持用户在任何阶段回退到上一阶段进行修改
- **FR-050**: 系统 MUST 在会话中记录交互历史，用于上下文传递和优化生成

### Key Entities *(include if feature involves data)*

#### 三阶段协作式创作核心实体

- **创作会话 (CreationSession)**: 代表一个多阶段创作会话，包含：会话ID、用户输入、当前阶段、生成的金句列表（用于退回时恢复）、选定的金句、内容大纲、生成的脚本、创建时间、更新时间、交互历史
- **金句 (Hook)**: 代表阶段1生成的金句选项，包含：金句ID、文本内容、所属会话ID、是否被选中、生成时间
- **内容要点 (ContentPoint)**: 代表阶段2生成的内容要点，包含：要点ID、标题、详细内容、顺序、所属会话ID、是否已展开

#### 生成结果实体

- **脚本大纲 (ScriptOutline)**: 代表AI生成的一个脚本方案，包含：脚本风格类型、标题、结构化要点列表、描述、专业元素（情绪锚点、记忆点、冲突设计、信息密度）、所属会话ID
- **Hashtag建议 (HashtagSuggestion)**: 代表一个Hashtag标签建议，包含：标签文本、相关度评分（可选）、类别（可选）
- **音乐风格建议 (MusicStyleSuggestion)**: 代表音乐风格描述，包含：风格描述文本、情绪描述、节奏描述、适用场景说明

#### 辅助实体

- **创作请求 (CreationRequest)**: 代表用户的一次创作意图输入（已由CreationSession替代，保留用于向后兼容），包含：输入文本、语言类型（中文/英文）、提交时间戳
- **生成结果 (GenerationResult)**: 代表一次完整的AI生成结果（legacy，已由CreationSession替代），包含：3个脚本大纲、5-10个Hashtag、1个音乐风格建议、生成状态（成功/失败/部分成功）
- **API日志 (APILog)**: 代表一次API调用的记录（仅在数据库启用时使用，可选功能），包含：请求时间戳、用户输入、使用的模型、提示词版本、生成的响应、响应时间、调用状态

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可以在30秒内完成从打开应用到提交创作主题的完整输入流程
- **SC-002**: 系统在每个阶段（Stage 1/2/3）的AI API调用，能够在15秒内完成并返回生成结果（在正常网络条件下）
- **SC-003**: 90%的API调用能够成功返回完整的生成内容（Stage 1: 3-5个金句；Stage 2: 3个内容要点；Stage 3: 3个脚本 + 5-10个Hashtag + 音乐建议）
- **SC-004**: 生成的脚本大纲必须包含至少3个结构化要点，每个脚本风格明显不同
- **SC-005**: 生成的Hashtag数量在5-10个之间，且与输入主题相关度达到80%以上（可通过人工评估）
- **SC-006**: 用户可以在5秒内完成复制任意生成内容到剪贴板的操作
- **SC-007**: 当API调用失败时，系统在3秒内显示错误提示，用户能够理解错误原因
- **SC-008**: 系统支持处理中英文混合输入，识别准确率达到95%以上
- **SC-009**: 在移动设备和桌面设备上，卡片式布局都能正常显示，响应式设计适配不同屏幕尺寸

## Assumptions

- 用户具有基本的网络连接能力
- 阿里云百炼API服务可用且稳定
- 用户理解短视频创作的基本概念
- 用户输入的创作主题是合理的（非恶意输入、非完全无关内容）
- 系统不需要用户身份认证（MVP阶段为匿名使用）
- **会话状态持久化是必需的**：三阶段协作式创作流程需要会话状态持久化，支持刷新后恢复和阶段回退。这需要数据库支持（SQLite）。
- **API日志记录是可选的**：SQLite数据库用于会话持久化（必需）和API日志记录（可选，用于开发调试）
- 音乐风格建议仅提供文字描述，不提供实际音频文件或链接

## Out of Scope (MVP)

以下功能明确不在MVP范围内：

- 用户账户系统和登录功能
- **用户可见的历史记录保存和查看功能**（产品功能不需要数据库）
- 脚本编辑和自定义功能
- 实际音频文件播放或下载
- 多轮对话和上下文理解
- 内容审核和过滤功能
- 社交分享功能
- 数据分析和统计功能（产品功能）
- 移动端原生应用（仅Web应用）

### 数据库使用说明

**数据库（SQLite）的使用范围**：
- ✅ **会话持久化（必需）**：三阶段协作式创作流程需要会话状态持久化，数据库是必需的
- ✅ **API日志记录（可选）**：开发环境默认启用API日志记录，生产环境可通过环境变量控制
- ✅ **环境变量控制**：通过 `ENABLE_DATABASE=true/false` 控制数据库功能，但会话持久化功能必须可用
- ⚠️ **生产环境**：数据库必须启用以支持会话持久化，但API日志记录可以禁用

## Architecture: Database Pattern for Session Persistence

### 设计原则

系统采用**会话持久化数据库模式**（Session Persistence Database Pattern）：

1. **数据库是必需的（会话持久化）**
   - 三阶段协作式创作流程需要会话状态持久化
   - 会话持久化是核心功能，不是可选功能
   - 数据库用于会话状态存储和API日志记录（可选）

2. **会话持久化是核心功能**
   - 启用数据库：设置 `ENABLE_DATABASE=true`，系统支持会话持久化和API日志记录
   - 数据库必须可用以支持会话功能
   - 会话状态存储在 `creation_sessions` 表中

3. **开发环境默认启用，生产环境必须启用**
   - 开发环境：`NODE_ENV=development` 时，默认 `ENABLE_DATABASE=true`
   - 生产环境：`NODE_ENV=production` 时，必须启用数据库以支持会话功能
   - API日志记录可以通过配置控制（可选功能）

4. **数据库文件自动管理**
   - 数据库文件自动创建和管理
   - 会话数据定期清理（可选，可配置）

### 实现要求

- **FR-020**: 数据库连接失败时，系统 MUST 显示错误提示，会话功能不可用
- **FR-021**: 数据库操作 MUST 使用try-catch包装，失败时记录错误，但会话操作必须成功
- **FR-022**: 数据库日志记录（API日志）MUST 是异步操作，不阻塞API响应
- **FR-023**: 系统 MUST 在启动时检测数据库可用性，如果不可用则显示警告，会话功能受影响

## Documentation Requirements

### 文档命名规范

- **FR-024**: 所有由AI工具（如Cursor）生成的论述型Markdown文档（.md文件）MUST 在文件名开头添加序号，格式为：`[序号]_[文档名称].md`
- **FR-025**: 序号必须按照文档生成的时间顺序递增（1, 2, 3, 4...），以便理清文档的生成顺序和依赖关系
- **FR-026**: 序号与文档名之间使用下划线（_）分隔，不使用空格或连字符
- **FR-027**: 文档名称应使用描述性的中文或英文名称，清晰表达文档内容

**命名示例**：
- ✅ 正确：`1_SPEC使用指南.md`
- ✅ 正确：`2_技术选型讨论.md`
- ✅ 正确：`3_开发调试存储方案.md`
- ✅ 正确：`4_SPEC更新说明-可选数据库.md`
- ❌ 错误：`SPEC使用指南.md`（缺少序号）
- ❌ 错误：`1-SPEC使用指南.md`（使用连字符而非下划线）
- ❌ 错误：`SPEC使用指南_1.md`（序号位置错误）

**适用范围**：
- 适用于项目根目录下的所有论述型文档
- 不适用于spec-kit规范文档（如`spec.md`、`plan.md`等）
- 不适用于代码文件中的注释文档
- 不适用于README.md等标准文档

**目的**：
- 便于追踪文档生成顺序
- 便于理解文档之间的依赖关系
- 便于项目文档管理和维护
